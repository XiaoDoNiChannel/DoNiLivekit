# 房间工作区与共享交互

本次保留现有语音频道模型。默认中央展示完整聊天，用户主动观看后才显示共享画面；随播聊天可收起。返回聊天只是切换视图，不停止收听。左侧服务器菜单收纳地址与昵称，空频道只显示一行，点击成员可以展开接收音量。

## 共享规则

- 屏幕共享仅发布视频：`audio: false`、`systemAudio: exclude`。程序音频继续由 Rust 9001 捕捉，与屏幕独立开启和停止。
- 房间连接使用 `autoSubscribe: false`。语音轨道显式自动订阅，屏幕和程序音频等待用户分别点击观看、收听；旧客户端的 WebView 屏幕音频不自动接收。
- 同一成员的画面、程序音频归为一组，但没有隐式关联。一次观看一路画面，切换来源只改变画面订阅。
- 共享开始时出现非阻断通知，8 秒后收起。忽略后，房间共享列表和成员下方仍有入口。
- 同一次共享不重复提醒；重连时匹配成员、媒体类型和轨道名称，保留用户的选择。停止后重新发布是一段新共享，需要重新选择收听。
- 画面结束不会自动跳到别人画面。停止观看不停止独立收听；离开房间会停止本人的共享并清理订阅、远端播放路由和本地管线。
- 程序音频的轨道名称采用 `app-audio:程序名称`。多个程序仍由现有 Rust 管线混合为一条轨道，发送音量控制这一混合结果，并非逐进程混音。

## 控制入口

- 麦克风：单击开关，悬停或点击箭头切换设备；同设置页共用设备动作。
- 耳返：独立按钮，使用现有 Rust 麦克风耳返链路。
- 屏幕共享、程序音频：两个独立按钮。
- 音频调节：自己的程序音频发送音量、麦克风输入电平、增益、阈值。
- 成员下方：自己收到的成员语音与程序音频音量，并可停止收听。
- 浮窗：直接显示或隐藏，箭头进入现有浮窗设置。聊天浮窗等后续内容未在此次实现。

## 验证

执行 `npm test --prefix ui`、`npm run build --prefix ui`。

自动测试覆盖独立订阅、多人切换、晚到轨道、通知去重、重连换 SID、重新共享、订阅失败重试、即时静音、离开时释放资源，以及屏幕仅视频捕获。

浏览器使用模拟共享状态检查聊天/观看布局、收听按钮、麦克风快捷菜单、音频调节、成员音量与 900px/1360px 窗口。模拟状态仅注入测试浏览器，不进入产品源码。

桌面端仍需两台客户端联调：真实 Rust 程序捕捉、麦克风热切换、屏幕选择器、播放与耳返、断网重连、浮窗快捷键。这些依赖实际设备和服务，浏览器模拟验证不能代替。
