# 队伍浮窗

在底部工具栏打开浮窗，或进入“设置 → 游戏浮窗”。右上角箭头切换精简与展开布局，两种布局分别记住大小。保留背景透明度、位置恢复及快捷键；窗口化与无边框全屏优先，独占全屏需按游戏验证。

- 精简布局：麦克风、在线人数、未读／提及数、最新消息与近期队伍动态。动态在 12 秒后让位于通话状态。
- 展开布局：消息、动态、语音、状态四页；新消息与动态不会自动切换当前页面。
- 消息跟随主界面正在浏览的**聊天频道**，在页面上独立标明；窗口标题和队伍动态属于当前**语音频道**。两者可以不同。
- 消息显示最近 30 条，支持纯文本发送（最多 2000 字符）、Enter 发送、Shift+Enter 换行、中文输入法、发送状态、未读／提及数与手动全部已读。收到的长消息有截断提示。草稿按通话会话和聊天频道保留在浮窗内存中，关闭应用后不保留。
- 动态记录本次通话的成员进出、屏幕与程序音频共享变化，保留最近 30 条；同批成员进出合并。首次加入和重连只建立基线，不生成整队加入／离开的提示。换通话后清空。
- 语音提供麦克风开关、Rust 麦克风输入电平、成员语音与程序音频收听音量（0–300%）。成员用文字显示，不显示头像或说话高亮。
- 状态显示连接、链路 RTT、语音接收丢包、语音抖动、自己的共享状态与已有诊断异常。缺失或超过 10 秒的统计显示为“—”，不会当成零。

默认 `Ctrl+Alt+Shift+O` 显示／隐藏，`Ctrl+Alt+O` 切换操作／鼠标穿透；操作模式下 Esc 返回穿透。穿透时无法输入、点击或调整音量。投票和组队卡未接入。

## 实现边界

主窗口仍是聊天 WebSocket、LiveKit 和音频的唯一所有者。`features/overlayTeam.js` 构造精简快照与队伍动态；`overlayProtocol.js` 将动作交给已有业务入口。浮窗不建立第二条媒体或聊天连接。

Rust `commands/overlay.rs` 校验窗口来源、快照新鲜度、会话、聊天频道、成员及操作参数，再转发到主窗口确认。主窗口再次验证；聊天发送还在异步连接等待之后检查目标频道。状态超过 6 秒未更新时禁用业务操作。消息写入网络后仍显示“发送中”，最终发送状态沿用现有服务端确认机制。

## 验证

- `cd ui; npm test`：包含队伍快照范围、动态基线／重连、动作参数与并发保护测试。
- `cd ui; npm run build`：两个前端入口构建。
- `cd src-tauri; cargo test --lib commands::overlay::tests --no-default-features`：原生权限边界、状态新鲜度、双布局尺寸恢复与动作校验。
- 启动 Vite `127.0.0.1:5183` 后执行 `node tests/overlay_team_smoke.cjs`。可通过 `PLAYWRIGHT_MODULE` 指向已有 Playwright 包。使用隔离的 Edge 无头浏览器和模拟原生传输，不连接真实账号、不发送真实消息。截图输出到 `tmp/overlay-team-qa/`。

真实多人通话、Windows 快捷键／鼠标穿透、不同显示器 DPI 与游戏全屏行为仍需桌面联调验证。
