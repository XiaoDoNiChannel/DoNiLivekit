# 通话诊断（第一批）

频道顶部的连接状态按钮打开诊断；右侧的聊天与诊断复用一个辅助区域。
窗口宽度不超过 1100px 时，辅助区域默认收起，主动打开后位于共享画面下方。
异常不会自动展开面板。聊天组件保留挂载，切换面板不丢失草稿；隐藏聊天时不标记消息已读。

## 数据和口径

- 使用 LiveKit 轨道公开的 `getRTCStatsReport()`，不读取 SDK 私有 PeerConnection 路径，不修改音视频轨道。
- 约每 2 秒采样；统计请求 3 秒超时，缺失值保持未知。采样属于 runtime，面板关闭后继续运行。
- 麦克风、共享音频、共享视频按 publication source/name 分开；未知来源音频不归入语音。
- 接收丢包使用每条 RTP 流近约 10 秒的 `ΔpacketsLost / (ΔpacketsLost + ΔpacketsReceived)`，首次采样或无新包时不显示假 0。轨道切换、计数器回退、长时间采样中断重建基线。成员之间按包数加权。
- 码率为对应窗口的字节增量；RTT、抖动以及存在的 `framesPerSecond` 为当前报告值。帧率字段缺失时回退到帧计数增量。
- 链路 RTT 取当前轨道关联的 selected candidate pair / remote inbound RTT 中的最大有效值，到媒体服务器的往返时间不等同于用户之间的端到端语音延迟。
- 本地共享目标来自本次实际启动共享时选择的设置，并绑定 track SID；实际发送分辨率、帧率和码率来自 outbound RTP。目标码率和帧率是上限。
- 远端共享仅展示本地可观测的接收/解码、丢包、冻结信息，不推测对方设置或对方编码瓶颈。
- 编码限制只在 `qualityLimitationReason` 明确报告 cpu/bandwidth 时给出对应建议。低帧率可能来自静止画面，不单独触发故障判断。
- 不支持的字段显示 `—`；缺失数据不能证明正常或故障恢复。

统计字段参考：[W3C WebRTC Statistics](https://www.w3.org/TR/webrtc-stats/)。具体字段是否提供仍以客户端 WebView2 的实际报告为准。

## 趋势、提示和事件

内存保留最近 2 分钟趋势、最近 100 条事件，退出应用即清空，不保存音视频内容。
切频道重置趋势和基线，事件保留频道名用于区分会话。

首版提示条件：接收丢包 >= 3%、链路 RTT >= 180ms、编码器报告 CPU/带宽限制，或接收端近约 10 秒出现冻结。
条件持续被观察至少 6 秒后生成一次提示，同一持续异常合并；指标恢复后记录恢复，统计缺失则记录无法判断。
这些阈值用于排查提示，不是链路质量保证或自动调整策略。

时间线还记录连接、重连、断开、开始/停止发送或接收共享。
“刚才卡了”可手动标记当前时刻。取消订阅也会产生停止接收事件，不直接判成故障。

## 验证

```powershell
npm test --prefix ui
npm run build --prefix ui
```

自动化覆盖：窗口丢包、计数器重置、迟到包修正、成员退出、共享和麦克风隔离、RTX 排除、设置与实测分离、冻结统计、持续异常合并、未知与恢复区分、重连、旧会话异步回写、超时和记录上限。

桌面实机验收：两台客户端加入同一频道；切频道/重连后确认诊断入口保留；共享动态画面检查目标与实测；缩放窗口并切换聊天/诊断；用受控网络/编码压力观察提示与恢复；验证 WebView2 实际提供的字段。
浏览器界面检查和模拟 RTC 报告测试不能代替上述 Tauri 双端验收。

本批不包含设备变化助手、麦克风体检、独立悬浮窗、游戏配置预设或自动更改共享参数。
