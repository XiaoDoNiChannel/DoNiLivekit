# 大厅与组队卡

## 这一版的交互

- 主大厅保留语音、屏幕共享和文字聊天能力。迁移时把最早创建的频道显示为「主大厅」，保留原 ID（通常为 day0）与聊天记录。
- 中间是当前浏览频道的聊天，右侧是游戏意向卡；主大厅展示全部卡片，游戏频道展示以它为目标的卡片。
- 点击左侧频道只浏览，不切换语音。点击「加入此语音／加入语音」才切换连接。底部仍显示实际语音频道。
- 观看共享时中间显示画面，右侧默认聊天，可反复切换聊天／组队卡；切换不销毁聊天输入框和视频容器。小窗口上下排列。
- 顶部链路按钮打开真实诊断抽屉。诊断临时覆盖右侧，不改变共享画面的布局。
- 频道加号打开创建表单，默认不跳转，可勾选创建后加入。任何在线成员都可以创建或删除空闲游戏频道；固定主大厅不能删除。

## 卡片语义与生命周期

卡片保存游戏名、发起人、招呼内容、可选目标频道和明确点选的意向成员。支持同一频道多张卡、同一人多个意向。人数标注「在线成员想玩」「离线」「语音内」，不推断正在游戏、队伍满员、缺几人或已开局。

发起人可以编辑和删除自己的卡片；删除卡片同时撤下意向记录，不删除频道、不移动任何成员。其他人可以随时加入或撤回意向。卡片展示内容更新时间，离线和重启不会自动删除；首版由发起人手动维护，不自动过期，不使用 LLM 或进程识别猜测状态。

删除频道会清除关联卡片的目标频道，保留卡片和聊天记录。已删除名称暂不复用，避免旧客户端或历史记录串入新频道。聊天记录保留在数据库中，首版没有归档浏览入口。

## 服务端升级

客户端和 Python 服务端均有改动，需更新并重启服务端才能使用卡片及频道删除；只有新客户端时会提示需要升级服务端。

数据库启动迁移至 schema 4，自动在原数据库旁生成迁移前备份。新增 rooms 的大厅标识／删除时间，以及 party_cards、party_interests 表。不应手动删除旧 rooms.db。

操作通过现有 Presence WebSocket 的 workspace_command 发送，workspace_result 确认；权威卡片和频道列表通过有版本的 presence_snapshot 同步。请求 ID 去重、编辑版本检查、断线／超时提示避免静默失败；断线不自动重放写操作。

删除频道先检查 Presence 和 LiveKit 成员；LiveKit 不可用时拒绝删除。仅归档应用频道，LiveKit 空房间自行过期，不主动踢人；归档后拒绝签发新 token。此前签发但尚未使用的 token 仍可能短暂连入原 LiveKit 房间，这不是严格的准入锁。

权限沿用项目现有局域网身份模型。卡片写入者取自当前有效 Presence 会话，不信任操作正文里的 ownerId；这不是账号认证系统，不能防止恶意客户端在建立连接时冒用身份。

## 验证

`npm test --prefix ui`、`npm run build --prefix ui`，以及 `python -m unittest discover -s tests -p '*tests.py'`。

新增用例覆盖共享侧栏切换、稳定身份意向计数、命令确认／超时／断线、卡片增删改与版本冲突、频道删除约束、广播、真实 WebSocket 路由和 v3→v4 保留历史的迁移。数据库测试仅使用临时数据库；LiveKit 服务操作使用测试替身，仍需部署后用两台客户端验证实际媒体共享与通话。
